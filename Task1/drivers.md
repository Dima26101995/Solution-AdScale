# Архитектурные драйверы

## 1. Подход

Драйверы определяют выбор архитектурных решений. Делятся на три группы:
- **Функциональные требования** — что система должна делать с точки зрения пользователей и бизнес-процессов.
- **Атрибуты качества (NFR, non-functional requirements)** — как система должна себя вести: насколько быстро, надёжно и безопасно.
- **Ограничения** — условия, которые нельзя обсуждать: технические (стек, инфраструктура),
  бизнес-ограничения (сроки, бюджет) и организационные (состав и компетенции команды).

Атрибуты качества приведены по стандарту ISO 25010.

## 2. Функциональные требования (к системе после интеграции с DSP)

| Категория | Драйвер | Значение |
|---|---|---|
| Функциональное требование | Запуск рекламных кампаний и управление бюджетами и ставками | Хранение и быстрое изменение кампаний, бюджетов, ставок; таргетинг |
| Функциональное требование | Управление рекламой в личном кабинете рекламодателя | Единая точка работы с рекламой: от создания кампании до аналитики |
| Функциональное требование | Участие в RTB-аукционах в реальном времени | Приём bid-request, аукцион, выдача bid-response в рамках SLA |
| Функциональное требование | Показ рекламы пользователям сайтов и приложений | Формирование и выдача рекламной разметки |
| Функциональное требование | Сбор данных о показах и кликах | Регистрация событий с высокой нагрузкой на запись |
| Функциональное требование | Аналитика и отчётность | Агрегация данных, построение отчётов |
| Функциональное требование | Расчёты с рекламодателями: списание, счета, балансы | Транзакции, консистентность данных |
| Функциональное требование | Пополнение рекламного бюджета | Взаимодействие с платёжным шлюзом, зачисление средств |
| Функциональное требование | Интеграция с DSP-партнёрами | Приём трафика нового DSP, обмен по OpenRTB |
| Функциональное требование | Мультиплатформенная интеграция (целевое, год) | Подключение нескольких площадок и платформ |

## 3. Атрибуты качества (приоритизированы)

Приоритет отражает влияние на выполнение SLA и контрактных обязательств: P0 — критично для запуска
интеграции с DSP, P1 — важно, P2 — желательно. Атрибуты качества нельзя максимизировать одновременно:
при конфликте приоритет отдаётся P0.

| Категория | Драйвер | Значение | Приоритет |
|---|---|---|---|
| Атрибут качества | Performance (производительность — время отклика и пропускная способность) | P95 ≤100 мс для аукциона, ≤80 мс для DSP | P0 |
| Атрибут качества | Scalability (масштабируемость — способность справляться с ростом нагрузки) | 18 000 RPS (3 мес) → 50 000 RPS (год), горизонтальное масштабирование | P0 |
| Атрибут качества | Availability (доступность — доля времени, когда система доступна) | SLA 99.9% (год), мультирегиональное развёртывание, без простоев при миграции | P0 |
| Атрибут качества | Reliability (надёжность — корректное выполнение функции без сбоев) | Нет сбоев сервиса ставок; нет потери событий и денег | P0 |
| Атрибут качества | Security (безопасность — защита данных и доступа) | Аутентификация партнёров (mTLS/API key), защита от несанкционированного доступа | P1 |
| Атрибут качества | Modifiability (изменяемость — лёгкость внесения изменений) | Независимая поставка сервисов, изменения без остановки системы | P1 |
| Атрибут качества | Maintainability (сопровождаемость — простота диагностики и устранения проблем) | Диагностика и поддержка при малой команде (нет SRE) | P2 |

## 4. Ограничения

| Категория | Драйвер | Значение |
|---|---|---|
| Техническое ограничение | Стек | C++ / Go / Python / Node (гибридный монолит) |
| Техническое ограничение | База данных | Одна PostgreSQL, общая схема для всех модулей |
| Техническое ограничение | Инфраструктура | Кеша, очередей и контейнеризации нет; один production-кластер; ручной деплой |
| Техническое ограничение | CI/CD | Отсутствует; нет быстрого rollback |
| Техническое ограничение | Документация | Архитектура не задокументирована |
| Бизнес-ограничение | Сроки | 3 месяца до подключения DSP |
| Бизнес-ограничение | Бюджет | Ограничен: нельзя нанять большой штат |
| Бизнес-ограничение | Возможность изменений | Систему нельзя переписать полностью — только постепенная миграция |
| Бизнес-ограничение | Непрерывность бизнеса | Платформу нельзя останавливать |
| Бизнес-ограничение | Контрактные обязательства | Штрафы DSP за деградацию времени отклика и простои |
| Организационное ограничение | Команда | 35 человек; нет SRE, BA, технического писателя |

## 5. Ключевое противоречие

Атрибуты качества (P95 ≤100 мс, 18 000 → 50 000 RPS, SLA 99.9%) противоречат текущему состоянию
системы (монолит, одна PostgreSQL без кеша, очередей и реплик). Именно это противоречие — отправная
точка архитектурных решений и определяет стратегию эволюции.
